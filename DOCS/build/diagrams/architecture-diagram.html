Fnaf_CV — architecture reference

Hands-free FNAF: gesture cursor + click, sensing to actuation

MediaPipe tracks the hand every frame — its position drives the mouse cursor and its crop feeds a transfer-learned classifier that reads palm (no click) vs. fist (click). Confirmed clicks fire into the real game via simulated DirectX input. Three subsystems: an offline training pipeline, an orchestration/deployment layer added in Week 4, and the online real-time loop that actually plays the game.

Offline

Runs once per training cycle on the local RTX 4060 (AD-02b). Produces a self-describing checkpoint — backbone, classes, and input spec travel with the weights.

Orchestration

Added Week 4. Event-triggered, not scheduled (--if-data-changed) — a static dataset has nothing to run on a clock. Moves the champion alias when a run wins.

Online

The loop actually playing the game. One thread, ESC is a global kill-switch that freezes the cursor and releases any held click before disabling output.

Artifact / game

The registry is the single answer to "which model is live"; FNAF is the unmodified Steam game, not a clone — every control is a hover or a click.

The contract that keeps it honest

§A.3 Train/serve preprocessing must be byte-identical. src/rt/preprocess.py calls the same build_transforms(train=False) used offline — size, interpolation, normalization, crop policy all shared, not re-implemented. This is the most common cause of "great test accuracy, useless live."
AD-25 The crop source half of that contract was violated, then measured and fixed (2026-07-28). Training pads HaGRID's annotated bbox; the live loop pads MediaPipe's 21-landmark hull — same 0.15 pad, two different boxes, and a hull runs ~0.77× smaller than a bbox. Worst on fist (0.705×), the one class that fires clicks. Live pad recalibrated 0.15 → 0.35; real fist click-rate at the FSM gate rose 81.5% → 94.4% with false clicks 0.7% → 0.0% on held-out stills. The live A/B against the actual running game is still open.

Key decisions behind this shape

ADDecisionWhy it's shaped this way
AD-04Two-stage: detect-then-classifyFull-frame classification hit only 57% val — the hand is <5% of a typical frame. MediaPipe crops for free, no second model to train.
AD-17Pivot to cursor + click (not a gesture vocabulary)FNAF is entirely mouse-driven. One universal interaction beats an 8-gesture map where every misread was a wrong in-game action.
AD-18 / AD-21Binary head: fist vs. not_fistPalm/fist is the maximal-separation pair; widening the negative class to six gestures makes "unknown pose → no click" the model's default.
AD-19Adaptive-control-box cursor mappingFixed absolute mapping made cursor gain distance-dependent; box width now scales with palm span so the same arm motion moves the cursor the same amount at any distance.
AD-20Edge-triggered click, K-frame debounceFNAF has no drag/hold interaction, so hold-while-fist buys nothing and adds a flicker failure mode. Re-arm requires a confirmed palm — double-fires become structurally impossible.
AD-23A ~200-line local DAG, not AirflowOne machine, a static dataset, nothing arrives on a clock — a scheduler daemon would be ceremony with no job to do.
AD-24MLflow registry + self-preprocessing pyfuncPreprocessing is half the train/serve contract; bundling it in the versioned artifact makes drift structurally impossible for a served model.
AD-25Recalibrate live crop pad, 0.15 → 0.35Closed a hull-vs-bbox geometry gap that was silently starving the classifier's confidence on real fists — see contract callout above.
