# Strategy 3.2 — `fist` vs. `not_fist` (unknown poses → no-click)

**A retrain of [Strategy 3](03-cursor-and-click.md)'s click classifier**, keeping
the entire cursor + click pipeline (3.1 / 3.1.1) unchanged. Same backbone, same
crop contract, same FSM — only what the **negative class means** changes. See
[AD-21](../../architecture-and-decisions.md).

## The problem 3.2 fixes

The Strategy-3 model (AD-18) has two outputs and was trained on **only** `palm`
and `fist` crops. A softmax with two classes must put its mass on one of them —
so when the live hand does *anything else* (points, an "ok" sign, a relaxed
half-curl, the in-between frames of a slow squeeze), the model is **forced** to
choose palm or fist. It never learned those poses, so it can land confidently on
`fist` → an **accidental click**.

The click FSM's confidence gate (AD-20) catches *some* of this, but it's a
band-aid over a model that literally cannot represent "this isn't a fist." The
failure we care about — a **false click** — comes from out-of-distribution hand
shapes, not from palm↔fist confusion.

## The reframe

> **If it isn't a confident fist, it's no-click** — learned by the model, not
> left undefined.

Keep the head binary, but redefine class 0:

| idx | class | meaning | trained on |
|---|---|---|---|
| 0 | `not_fist` | **no click** | `palm, one, two_up, like, dislike, mute` (6 diverse gestures) |
| 1 | `fist` | **click** | `fist` |

The negative class now spans many hand shapes, so "unknown → no-click" becomes
the model's *default* behaviour. `fist` is the one pose that has to be crisp;
everything else collapsing to no-click is exactly the interaction we want.

## How it's built (data layer, AD-21)

Two small, backward-compatible additions to the data pipeline — the palm/fist
config (AD-18) still runs unchanged:

- **`label_groups`** (`configs/data_fistvsrest.yaml`): maps each target label to
  the image folders that feed it. Several gesture folders collapse into one
  class. The crop is still each folder's **own** hand bbox (we crop the gesture
  the folder is about); only `label`/`label_idx` are the grouped target.
  ```yaml
  classes: [not_fist, fist]
  label_groups:
    fist:     [fist]
    not_fist: [palm, one, two_up, like, dislike, mute]
  balance: true
  ```
- **`balance: true`**: `not_fist` has ~6.4k images across six folders vs `fist`'s
  ~1.1k. Balancing downsamples `not_fist` to the `fist` count, drawn **evenly
  across the six sources** (so the negative stays diverse, not dominated by one
  gesture) and **seeded** (identical every run). No loss weighting needed.

Realised balanced index (seed 42):

```
by target label:   not_fist 1097   fist 1097
not_fist by source: mute 184  one 183  palm 183  dislike 183  two_up 182  like 182
split (by user):    train 1559   val 308   test 327   (per-class ≈ balanced)
```

Same AD-16 user-grouped 70/15/15 split (no subject leakage) and AD-04 bbox crop
as every other strategy.

## Decisions made (Ted delegated these for 3.2)

- **Negative-class name `not_fist`** (not "palm") — the confusion matrix and
  report then tell the truth about what class 0 is. Runtime cost is zero: the
  checkpoint carries its class list and the FSM already takes the no-click label
  as a parameter.
- **Which gestures feed `not_fist`** — the six non-fist gestures already
  downloaded. No new acquisition.
- **`ok` held out of training entirely** — reserved as an **unseen** gesture for
  the open-set check below.
- **Balance by downsampling** (vs. class-weighted loss) — keeps the frozen
  linear-probe fast path and stays directly comparable to the palm/fist run.
- **Frozen linear-probe recipe**, identical to `palmfist_frozen` — so 3.2 vs 3.0
  is a clean A/B, not a recipe change. Unfreezing / 2.1 aug knobs remain Ted's
  later call if the numbers ask for it.

## Runtime changes

Only the FSM's no-click label had to become checkpoint-derived (the pipeline is
otherwise identical):

- `src/control/play.py` — accepts any **binary** click model (exactly 2 classes
  incl. `fist`); the no-click label is whichever class isn't `fist`, passed to
  `ClickFSM(palm_label=..., fist_label="fist")`. Works for palm/fist **and**
  not_fist/fist.
- `src/rt/webcam_demo.py` — same derivation for the click preview; legacy
  multi-class checkpoints keep the `"palm"` default.
- `src/control/click_fsm.py` — no logic change; its `palm_label`/`fist_label`
  params were already the seam. Docstring updated.

Preprocessing, crop geometry, cursor mapping, kill-switch: **unchanged** — a 3.2
checkpoint is a drop-in for a 3.0 one.

## How to train

```bash
python -m src.train --config configs/fistvsrest_frozen.yaml
```

Writes `models/fistvsrest_frozen_mnv3_large/best.pt` (+ resolved config) and an
honest report (val + held-out test, per-class P/R/F1, confusion matrix). Then run
it live exactly like the palm/fist model:

```bash
python -m src.rt.webcam_demo --checkpoint models/fistvsrest_frozen_mnv3_large/best.pt
python -m src.control.play    --checkpoint models/fistvsrest_frozen_mnv3_large/best.pt --dry-run
```

## Evaluation — the number that matters

Trained 2026-07-20 (frozen linear-probe, seed 42): **best val 0.9221, test
0.9358** (per-class F1 not_fist 0.9307 / fist 0.9402). That raw accuracy is
*lower* than palm/fist's 0.9815 **by design** — `not_fist` is a far harder
negative (six gestures, some partly closed). Raw accuracy is not the point on a
balanced binary task (random = 50%). The metric that is: the **open-set
false-click rate** from `src/eval_openset.py` — how often each model fires `fist`
on a non-fist gesture (250-img seeded sample, conf-gate 0.70 = the FSM's click
threshold):

| gesture | palm/fist click% | **fist-vs-rest click%** |
|---|---|---|
| **fist** *(want HIGH)* | 99.2 | **96.0** |
| palm | 0.4 | 0.8 |
| one *(pointing!)* | 75.6 | **9.2** |
| two_up | 81.2 | **2.4** |
| like | 41.2 | **2.8** |
| dislike | 74.4 | **3.2** |
| mute | 60.4 | **0.0** |
| **ok** *(unseen by BOTH)* | 6.8 | **0.8** |

Reading it:

1. **The palm/fist model false-clicks constantly on ordinary poses** it never
   trained on — a *pointing* hand fires a click 76% of the time, `two_up` 81%,
   `mute` 60%. Those are exactly the incidental shapes a hand drifts through
   while driving a cursor. This is the accidental-click problem 3.2 targets.
2. **Fist-vs-rest collapses them to 0–9%.**
3. **`ok`, unseen by both models, still goes 6.8% → 0.8%** — the diverse
   negative generalises "unknown → no-click" to a pose it never saw. That's the
   open-set evidence, not memorisation.
4. **The honest cost:** `fist` click-rate 99.2% → 96.0% — ~3% of real fists read
   as not_fist (the 13/327 fist→not_fist test errors). Fewer false clicks bought
   with slightly less eager true clicks; the FSM's K-frame confirm softens it (a
   briefly-missed fist just needs the squeeze held one more frame).
