# Strategy 3.2.1 — snappier click FSM (conf 0.80 / K 2)

**A pure *tuning* variant of [Strategy 3.2](03.2-fist-vs-rest.md), not a new
model.** Same fist-vs-rest checkpoint, same cursor pipeline, same crop contract,
same grace window and cooldown. The **only** thing that changes is two knobs on
the click FSM (AD-20):

| knob | 3.2 (steady) | **3.2.1 (snappy)** |
|---|---|---|
| `--fsm-conf` (per-frame confidence gate) | 0.70 | **0.80** |
| `--fsm-k` (consecutive frames to confirm) | 3 | **2** |

Everything else is identical, so 3.2 vs 3.2.1 is a clean A/B on *click feel* with
the model held fixed. Both are defined once in
[`src/control/strategies.py`](../../../../src/control/strategies.py) so `play.py`
and the eval dashboard resolve the same numbers.

## Why these two, and why together

The two changes deliberately pull in **opposite directions**, which is the whole
point of pairing them:

- **conf 0.70 → 0.80 (stricter per-frame gate).** Fewer frames "count" — a frame
  now needs 80 % softmax to register as `fist` or `not_fist`, else it's
  *ambiguous* (neither confirms nor resets, tolerated by the grace window). This
  raises the bar a marginal or in-between pose must clear to advance a streak,
  cutting the confidently-wrong frames that cause false clicks.
- **K 3 → 2 (looser confirm).** A confirmed pose fires after 2 consecutive
  confident frames instead of 3 — one fewer frame of latency (~15–30 ms at
  30–60 FPS), so clicks feel snappier and a briefly-missed fist re-triggers
  faster. Re-arm also drops to 2 confident `not_fist` frames, so rapid
  intentional palm↔fist cycling gets easier.

**Net effect on false clicks is a wash *by design*:** we trade "3 frames at 0.70"
for "2 frames at 0.80" as the noise barrier. Whether that nets out safer or
riskier depends on the *shape* of the model's errors — and 3.2's whole reason for
existing (AD-21) is that the fist-vs-rest model's wrong predictions on unknown
poses are mostly **low-confidence** (a pointing hand fires only 9 % at conf 0.70,
`ok` 0.8 %). Against a model that fails *quietly*, raising the gate to 0.80 more
than pays for the weaker K=2 confirm — snappier **and** at least as safe. The
risk case is a model that is *confidently* wrong on some pose: there, K=2 lets a
2-frame flicker through and the 0.80 gate won't stop it. That's the same
model-vs-FSM boundary called out in
[controller-and-calibration.md](controller-and-calibration.md#L228-L230): if
false clicks persist at a sane gate, retrain — don't crank knobs.

> This is exactly why 3.2.1 is *tried and measured*, not assumed. The offline
> open-set false-click rate (`src/eval_openset.py`) at conf **0.80** predicts the
> per-frame half; the live re-test at arm's length is the verdict that counts.

## What it does NOT change

The model (`models/fistvsrest_frozen_mnv3_large/best.pt`), the cursor mapper
(3.1.1 adaptive box), MediaPipe detector, EMA / dead-zone smoothing,
edge-triggered single click, `not_fist` re-arm, the **grace window (10)**, the
**cooldown (0.30 s)**, the crop contract, and the kill-switch — all unchanged. A
3.2.1 run is a 3.2 run with two flags flipped.

## How to test it

**`play.py` (dry-run first, then live):**

```bash
# snappy variant
python -m src.control.play --checkpoint models/fistvsrest_frozen_mnv3_large/best.pt --strategy 3.2.1 --dry-run
python -m src.control.play --checkpoint models/fistvsrest_frozen_mnv3_large/best.pt --strategy 3.2.1

# steady baseline for the A/B
python -m src.control.play --checkpoint models/fistvsrest_frozen_mnv3_large/best.pt --strategy 3.2
```

`--strategy` sets `conf` + `K`; an explicit `--fsm-conf` / `--fsm-k` still
overrides it (e.g. `--strategy 3.2.1 --fsm-k 3` to isolate just the conf change).
Read the HUD's FSM streak counters (`fsm.describe()`) to see whether a missed
click is a confidence, `K`, or arming problem.

**Eval dashboard (pick the strategy in the page):**

```bash
python -m src.eval_dashboard.server --checkpoint models/fistvsrest_frozen_mnv3_large/best.pt
```

With a fist-vs-rest checkpoint the Start screen shows a **Click strategy** picker
(3.2 · steady / 3.2.1 · snappy). Choose one *before* pressing **Start hand
tracker** — the pick is baked into the loop at start and stamped onto the saved
run's **Strategy** column, so the Overview tab compares 3.2 vs 3.2.1 obstacle
scores directly. (The picker is hidden for palm/fist checkpoints, where the
preset names don't apply.)

## Verdict

*Pending live A/B.* The instrumentation (offline open-set at 0.80 + the dashboard
obstacle course) is in place; the number that decides 3.2 vs 3.2.1 is how the two
feel driving the real game at arm's length — same convention as 3.1 / 3.1.1 / 3.2.
