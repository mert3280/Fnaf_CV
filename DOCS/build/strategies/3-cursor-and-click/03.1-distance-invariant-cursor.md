# Strategy 3.1 — Distance-invariant cursor calibration

**Status: patched by [Strategy 3.1.1](03.1.1-live-robustness-fixes.md)** — the
3.1 live test found three remaining faults (touchy detection, slow squeezes
never clicking, distance *gain* still varying); 3.1.1 fixes them on top of
this page's anchor calibration, which stands unchanged.

**An incremental update to [Strategy 3](03-cursor-and-click.md), not a new
approach** — the 2.1-to-2 relationship, repeated. Same pipeline, same model,
same click FSM. What 3.1 changes is one thing: **how the cursor anchor is
calibrated**, so pointing works the same at any hand distance within reason.

## The live finding (Ted, 2026-07-15)

First live test of the Strategy-3 preview: the pipeline works, but there was
**too much of a distance issue** — cursor behavior changed with how far the
hand was from the camera. Requirement: the mapping must depend **only on where
the hand is pointing**, never on how big the hand or its detection box appears.

## The diagnosis — a real size coupling, not a tuning problem

The 3.0 anchor was computed from the detector's **pixel landmarks, which are
clipped to the frame** (`np.clip(..., 0, 1)` in `detector.py`). MediaPipe keeps
estimating landmarks *past* the frame edge, and clipping them has a
size-dependent effect:

- **Far / small hand** — the whole hand fits in frame, nothing clips, the
  anchor is honest.
- **Close / large hand** — fingers or wrist routinely fall outside the frame;
  their clipped coordinates get dragged to the frame edge, which **biases the
  anchor toward the frame interior**. Same physical pointing spot → different
  cursor position, and the bias grows as the hand gets closer/larger.

So the cursor *was* coupled to hand size, exactly as the live test felt.

## The fix — anchor = pure position from the frame's top-left

1. **`HandBox` now carries the unclipped normalized landmarks**
   (`landmarks_norm`) alongside the clipped pixel ones. The clipped values are
   still used for the classifier crop (a crop can't leave the frame) and the
   HUD; **only the cursor anchor switches to the raw values**.
2. **`hand_anchor_norm()`** (replaces `palm_anchor_norm`) reduces the hand to
   **one point measured from the frame's top-left** in normalized coords.
   Hand/box size appears nowhere in the computation — verified by test: the
   same shape at 9× the size, pointing at the same spot, produces a
   bit-identical anchor.
3. Anchors may now fall **outside [0, 1]** when part of the hand is off-frame;
   the control-box clamp handles that smoothly instead of the old clipping
   bias, so the cursor keeps tracking right up to the frame edge.

### The anchor point itself — `--anchor palm | box` (Ted's live A/B)

| Source | Point | Trade-off |
|---|---|---|
| `palm` *(default)* | mean of wrist + 4 finger-base landmarks (0, 5, 9, 13, 17) | stable through the palm→fist squeeze → no cursor lurch on click |
| `box` | center of the landmark hull ("middle of the box") | simplest to reason about; hull shrinks when fingers curl, so the anchor can dip slightly on the squeeze |

Both are size-invariant; the difference only matters during the click squeeze.
Flag exists on both `webcam_demo` and `play`.

## What did NOT change

Control box, EMA smoothing, dead-zone, freeze-on-dropout, the click FSM, the
model, and the crop contract are all untouched — 3.1 is strictly the anchor
calibration. All 3.0 tuning flags keep their meanings and defaults.

## What this does and doesn't fix

- **Fixes:** the cursor pointing differently at different hand distances (the
  calibration bias above).
- **Doesn't fix:** the *classifier's* accuracy at unusual distances — if
  palm/fist reads degrade close to the lens, that is the Strategy-2 domain gap,
  and its levers are unchanged (2.1 aug knobs, self-capture fine-tune at
  cursor distances). Watch the FSM: distance-related *click* failures are a
  model issue, distance-related *pointing* drift would be a mapper issue.
- **Physical note:** at long distances a comfortable arm sweep covers less of
  the frame; if screen corners get hard to reach, shrink the control box
  (`--box-w/--box-h`) to raise the motion gain — a tuning call, not a bug.

## Verification

Offline suite (32 checks) passes, including three new 3.1 checks: palm- and
box-anchor bit-identical across a 9× hand-size change, and the unclipped anchor
continuing to track when a third of the hand is off-frame (where the clipped
3.0 anchor visibly drags inward).

## How to run

```bash
# same commands as 3.0 -- 3.1 is the default behavior now
python -m src.rt.webcam_demo --checkpoint models/palmfist_frozen_mnv3_large/best.pt
python -m src.control.play   --checkpoint models/palmfist_frozen_mnv3_large/best.pt --dry-run

# A/B the anchor point live
python -m src.rt.webcam_demo --checkpoint models/palmfist_frozen_mnv3_large/best.pt --anchor box
```
