# Strategy 3.1.1 — Live robustness fixes (detection, click, distance gain)

**A patch to [Strategy 3.1](03.1-distance-invariant-cursor.md)** from its first
live test. Same pipeline, same model, same anchor calibration — 3.1.1 fixes the
three problems the test surfaced.

## The live findings (Ted, 2026-07-15)

1. **Detection is touchy** — sometimes the hand isn't found at all; fast
   movement loses tracking, and re-acquiring takes noticeable movement.
2. **Clicking works ~50%** — and a **slow** palm→fist never clicks at all;
   only a fast squeeze works reliably.
3. **The distance error is still there** — 3.1's position fix wasn't the
   (whole) distance problem.

## Fix 1 — Detection: default thresholds 0.5 → 0.3

MediaPipe's three confidence gates (`detection`, `presence`, `tracking`) all
defaulted to 0.5 — strict enough to miss valid hands and to drop tracking on
motion blur, after which the stricter *initial-detection* stage must re-fire
(the slow re-acquire Ted saw). All three defaults are now **0.3** in
`detector.py` and both CLI entry points: stickier lock, eager re-detection.

Trade-off: more risk of grabbing a non-hand. If that shows up, raise
`--detect-confidence` back toward 0.5 (this is 2.1's fix #6 knob — live
tuning, Ted's call). Brief dropouts that still happen are now also *bridged*
downstream: the cursor freezes (3.0 behavior) and the click FSM's new grace
window (fix 2) no longer punishes them.

## Fix 2 — Click FSM: a grace window instead of hard disarm

**The slow-fist bug was structural, not tuning.** The 3.0 FSM disarmed on the
*first* frame that was neither confident-palm nor confident-fist. A slow
palm→fist necessarily passes through half-curled poses the classifier is
unsure about — so mid-squeeze, the FSM hit an ambiguous frame, disarmed, and
the completed fist had nothing to fire from. Re-arming needs K *palms*, but
the hand is now a fist: **a slow squeeze could never click, by construction.**
Fast squeezes worked because they cross the ambiguous zone within a frame.
The same hard-disarm also amplified detection dropouts (problem 1) into missed
clicks — a large share of the "~50%".

**3.1.1 semantics:** ambiguous frames (low confidence, dropout, other label)
no longer reset or disarm anything — they just don't count. Only ambiguity
**sustained past `grace` consecutive frames** (default 10, ≈0.3–0.5 s) decays
the state. What is *unchanged*: firing still requires K confident fist frames
from an armed state, re-arming still requires K confident palms, and a hand
that actually left still disarms — so the safety properties (no phantom
clicks from noise or dropouts, no double-fires) survive intact.

New knob: `--fsm-grace` (frames). The HUD's FSM readout now shows a `?n/grace`
counter while ambiguity is being tolerated, so you can watch it work.

## Fix 3 — Distance: the control box now scales with hand size

3.1 made cursor **position** honest (a frame position = a screen position,
regardless of hand size). The live test showed that isn't the invariance that
matters: with a fixed box, the **gain** still changes with distance — up close
your hand spans much of the frame, so a small arm motion flings the cursor;
far back, the same motion barely moves it. That is the residual "distance
error."

**3.1.1 (`--box-mode adaptive`, the new default):** the control box's size is
proportional to the hand's apparent size — `width = gain × palm_span`, where
`palm_span` is the wrist→middle-knuckle distance (stable through the fist
squeeze, unlike the shrinking landmark hull). Hand appears half as big
(twice as far) → box is half as big → the same *physical* arm movement moves
the cursor the same amount. Verified: cursor travel for a half-hand-span
motion is identical (±1 px) at a 4× size difference.

**The honest trade-off:** position-invariance and motion-invariance are
mutually exclusive when distance changes. In adaptive mode, a fixed *frame
position* no longer maps to one fixed screen point across distances — your
*movements* map consistently instead, anchored on the frame-center = screen-
center line. The live tests asked for exactly this; if it feels wrong,
`--box-mode fixed` restores 3.1 verbatim.

Knobs: `--box-gain` (default 4.0; higher = less arm travel to cross the
screen), box aspect still from `--box-w`/`--box-h`. The HUD box now visibly
grows/shrinks with your hand — that's the mechanism working, not a bug.

## What did NOT change

The model/checkpoint, the crop contract, the anchor calibration (3.1), EMA/
dead-zone smoothing, edge-triggered single click, palm re-arm, cooldown, the
kill-switch. All 3.0/3.1 flags keep working; `--box-mode fixed` is the full
revert lever for fix 3.

## Verification

Suite extended to **39 checks**, all passing — new ones: slow palm→fist with
low-confidence middle frames fires exactly once (the 3.0 bug reproduced, then
fixed); one dropout frame mid-squeeze no longer cancels the click; sustained
absence (> grace) still disarms and cannot fire; same arm motion gives the
same cursor travel at 4× hand-size difference; fixed mode ignores hand scale.
Live re-test pending — that's the verdict that counts.

## How to run

```bash
# defaults now include all three fixes
python -m src.rt.webcam_demo --checkpoint models/palmfist_frozen_mnv3_large/best.pt

# revert levers / tuning surface (Ted's)
#   --box-mode fixed            3.1 static box
#   --box-gain 5.0              faster cursor per arm-inch
#   --fsm-grace 15              more tolerance for slow squeezes
#   --fsm-conf 0.6              count lower-confidence frames
#   --detect-confidence 0.5     stricter hand detection again
```
