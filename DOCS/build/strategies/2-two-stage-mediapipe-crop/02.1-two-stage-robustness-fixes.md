# Strategy 2.1 — Two-stage, hardened against the live distance gap

**An incremental update to [Strategy 2](02-two-stage-mediapipe-crop.md), not a new
approach.** The pipeline is unchanged — MediaPipe finds the hand, the same CNN
classifies the crop. What 2.1 adds is a set of **robustness fixes** aimed squarely
at the one problem the live test exposed: the classifier is accurate when the hand
is held **near the body** (matching HaGRID's at-a-distance training data) and
degrades when the hand is held **close to the webcam** (perspective/scale/focus the
model never trained on).

> **Relationship to 2.0:** 2.0 = "does the two-stage pipeline work?" (yes, 92%
> offline / reads gestures well live). 2.1 = "make it hold up across hand
> distances and framings." Same checkpoint still runs; the fixes are either
> live-loop aids (no retrain) or opt-in training/data levers.

> **Status:** fixes **1, 2, 6 are live now** (runtime-only, in the demo). Fixes
> **3, 5** are implemented as **code knobs, defaulted OFF** — they change nothing
> until Ted opts in and **retrains**. Fix **4** ships a **capture tool**; the
> fine-tune itself is Ted's to run. Per project guardrails, the *mechanisms* are
> built here but the *modeling decisions* (aug magnitudes, unfreeze schedule,
> fine-tune recipe) stay Ted's.

---

## The six fixes — what, how, and where it lives in code

Legend: 🟢 live now (no retrain) · 🟡 needs a retrain Ted runs · 🔵 needs data + a retrain.

### Fix 1 — Framing hint 🟢
**What:** operationalize the "hold your hand at a natural distance" guidance so you
don't have to guess. The demo measures the detected hand's area as a fraction of
the frame and, when it's too large (hand close to the lens), overlays
`hand too close - move it back toward your body`.

**How it's implemented:**
- [`src/rt/detector.py`](../../../../src/rt/detector.py) — `HandBox.area_frac`
  (landmark-hull area ÷ frame area) as the closeness proxy.
- [`src/rt/webcam_demo.py`](../../../../src/rt/webcam_demo.py) — `framing_hint()`
  turns that fraction into the on-screen warning; threshold is `--near-frac`
  (default 0.40).

**Use:** just run the demo — the hint appears automatically. Tune the trigger with
`--near-frac 0.5` if your camera/room makes the default too eager.

---

### Fix 2 — Live pad tuning 🟢
**What:** MediaPipe's landmark box is *tighter* than HaGRID's annotated box, so the
crop the classifier gets isn't framed quite like training. `pad` grows the box;
tuning it live lets you find the framing the model likes without editing code.

**How it's implemented:**
- Crop geometry already flows through the shared `padded_bbox_pixels()`
  ([`src/data/dataset.py`](../../../../src/data/dataset.py)), and the detector reads
  `detector.pad` every frame — so mutating it takes effect immediately.
- [`src/rt/webcam_demo.py`](../../../../src/rt/webcam_demo.py) — `[` / `]` keys
  step `pad` down/up by `--pad-step` (default 0.05); the current value shows in the
  HUD footer. Set a starting value with `--pad`.

**Use:** `python -m src.rt.webcam_demo --checkpoint … --pad 0.15`, then press `]`
to loosen / `[` to tighten and watch confidence.
> ⚠️ **Caveat (Ted's call):** changing live pad *without retraining* trades one
> mismatch for another. The principled version is to pick the pad that reads best,
> then **retrain the bbox model at that pad** (`configs/data.yaml → input.bbox_pad`)
> so both halves match.

---

### Fix 3 — Perspective / blur augmentation 🟡
**What:** teach the classifier to tolerate webcam-close hands by simulating them in
training — perspective warp (foreshortening) and mild blur (fixed-focus softness),
on top of the existing jitter/rotation/RRC.

**How it's implemented (knobs only, default OFF):**
- [`src/data/config.py`](../../../../src/data/config.py) — `AugmentCfg.perspective`
  (RandomPerspective `distortion_scale`) and `AugmentCfg.blur_sigma`, both default
  `0.0`.
- [`src/data/transforms.py`](../../../../src/data/transforms.py) — the train
  pipeline adds `RandomPerspective` / `GaussianBlur` **only when the knob > 0**, so
  the baseline and current bbox runs are byte-for-byte unchanged.

**Use (Ted decides magnitudes, then retrains):** add to a training config's
`augment:` block, e.g. `perspective: 0.3`, `blur_sigma: 1.5`, set
`augment_train: true`, and rerun `python -m src.train --config …`. This is the
AD-09 augmentation call — magnitudes are a modeling decision, left to Ted.

---

### Fix 4 — Self-captured fine-tune 🔵
**What:** the most direct close of the domain gap — collect a few hundred frames of
*your* hands on *your* webcam at the distances you actually use, and fine-tune the
HaGRID model on them.

**How it's implemented (collection tool):**
- [`src/rt/capture_dataset.py`](../../../../src/rt/capture_dataset.py) — records
  crops through the **same detector + pad** as the live loop (so samples match
  inference exactly), into an ImageFolder layout `DATA/selfcapture/<class>/*.jpg`.
  Keys: `1-8` pick class, `SPACE` capture one, `c` continuous, `q` quit.

**Use:**
```bash
python -m src.rt.capture_dataset          # collect DATA/selfcapture/<class>/*.jpg
# then fine-tune (Ted's recipe): the images are already hand crops, so load them
# as crop_mode: full_frame and fine-tune the current checkpoint at a low LR.
```
> The fine-tune itself (epochs, LR, which layers, how to blend with HaGRID) is
> Ted's modeling decision and the AD-04 / Phase-5 open question — the tool only
> gathers the data.

---

### Fix 5 — Progressive unfreezing 🟡
**What:** let the backbone (not just the head) adapt to hand crops by unfreezing the
top block-stages with a small LR — AD-08 Stage B. More capacity to absorb the
webcam distribution.

**How it's implemented (mechanism only, default 0 = fully frozen):**
- [`src/models/build.py`](../../../../src/models/build.py) —
  `build_model(..., unfreeze_blocks=N)` calls `unfreeze_last_n_blocks()`, which
  re-enables grads on the last `N` of the backbone's 7 block-stages (MobileNetV3 /
  EfficientNet family). `N=0` leaves the current frozen behavior untouched.
- [`src/train.py`](../../../../src/train.py) — reads `model.unfreeze_blocks` from the
  config and **disables the linear-probe feature cache** when `N>0` (an unfrozen
  backbone isn't deterministic), falling back to the standard end-to-end loop.

**Use (Ted picks N + LR, then retrains):** add `unfreeze_blocks: 2` under `model:`
in a training config and rerun. *How many* stages and *when* is the freeze-schedule
decision AD-08 reserves for Ted; watch the train/val gap for overfitting.

---

### Fix 6 — Detection-confidence tuning 🟢
**What:** control how eagerly MediaPipe locks onto a hand — lower to catch more
hands (risking false grabs), raise to be stricter and cut jitter.

**How it's implemented:**
- [`src/rt/detector.py`](../../../../src/rt/detector.py) — the three thresholds
  (`min_detection_confidence`, `min_presence_confidence`, `min_tracking_confidence`)
  are separate constructor args.
- [`src/rt/webcam_demo.py`](../../../../src/rt/webcam_demo.py) — exposed as
  `--detect-confidence`, `--presence-confidence`, `--tracking-confidence`.

**Use:** `python -m src.rt.webcam_demo --checkpoint … --detect-confidence 0.3` if
"-- no hand --" shows too often; raise it if it grabs non-hands.

## Suggested order (recommendation, not a decision)

1. **Free, immediate:** Fix 1 + Fix 2 + Fix 6 — all live in the demo now. See how
   far good framing + a tuned pad + detection settings get you before touching the
   model. Read the best pad off the HUD.
2. **One retrain, no new data:** Fix 3 (perspective/blur aug) — cheapest model-side
   improvement; may be enough on its own.
3. **If still gapped:** Fix 5 (unfreeze a block or two) and/or Fix 4 (self-capture
   fine-tune) — the heavier, highest-ceiling levers.

Whatever the path: tune on **val**, report **test once** (AD-10); if a live pad is
adopted, retrain the crop at that pad so train and serve stay matched (AD A.3).

## What did NOT change

Same two-stage pipeline, same checkpoint, same [`padded_bbox_pixels`] crop contract
(training ≡ runtime), same auto-selection of crop source from `crop_mode`. 2.1 is
strictly additive — every fix is off/neutral by default, so nothing here silently
alters the current behavior or an existing training run.
